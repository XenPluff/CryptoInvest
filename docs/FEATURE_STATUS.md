## Rate interpretation

The supplied seven-day plans target 2.5%, 3%, 4%, or 5% per day. The supplied Shareholder plan targets 10% per month over 365 days. These unusually high inputs are displayed as illustrative targets with capital-at-risk disclosures; the application does not substantiate their attainability.

Daily target earnings are `principal × dailyRate × elapsedDays`, capped at the stored term. Monthly target earnings use `principal × monthlyRate × 12 × elapsedDays / 365`. Calculations use elapsed UTC milliseconds and exact rational arithmetic. The illustrative display floors the target to micro-dollars and renders six decimal places; the separate cent fields floor to whole cents. For a $100 Starter principal, the display advances from $100.000000 to $100.000028 after one second and $100.000057 after two seconds, while the cent fields still show $100.00. It reaches $117.500000 after seven days and remains fixed thereafter. The supplied Shareholder target projects $15,000 to $33,000 over exactly 365 days, including across leap years. Neither estimate adds withdrawable funds. The actual integer-cent ledger changes only when a verified event or reconciled settlement is recorded.

## Verification scope

Run `npm run typecheck`, `npm test`, `npm run test:integration`, `npm run build`, and `npm run test:e2e` as described in the README. Tests cover arithmetic, account and wallet security, newsletter consent, meaningful API authorization/ledger transitions, and browser workflows. The integration helper requires a nonproduction PostgreSQL connection with `CREATEDB`; it creates and drops a separate disposable database, preserving the application schema. Direct runs with `TEST_DATABASE_URL` reset only the selected dedicated `_test` database. Browser tests need a development/staging database and Mailpit. A passing run does not prove external custody, production email deliverability, regulatory status, or real investment performance.
